DMPC2000
Custom MPC2000 Classic OS

An unofficial firmware build for the Akai MPC2000 Classic. Extended features, and workflow improvements. Not affiliated with Akai Professional.

Songs saved with modified OS features might not load properly on stock 1.72 OS so keep this in mind.

I've been a software developer for over a decade. These updates are a result of reverse engineering the stock OS and modifying it to my liking. I have my own unit testing workflows, patch creation workflows, and a suite of reverse engieering tools to make this a possibility. If you have any questions, feature requests, or bugs, please contact me at imaginationdriver@gmail.com

2026-09-19 Resample Suite in the MPC 2k Classic feature

There is now a resample suite built directly into the MPC 2000 Classic. This feature is highly experimental and still a work in progress.

You can access it through the TRIM menu: TRIM -> Params -> Resamp. From there, you can select how many octaves you want to speed the sample up before resampling and copying it back into memory: 1 (-120) 2 (-240) 3 (-360) 4 (-480)

The main reason I wanted to get this working is the insane aliasing the MPC 2000 produces when pitching below -24 semitones. Buzzy basslines. Cosmic stardust-filled strings. Thick, warm, punchy drums ect. Instead of having to leave the MPC, pitch something up, resample it externally, and bring it back in, you can now do the whole process in the box. Sample something straight from vinyl and keep processing it in the MP.

This is going to eventually become a proper resampling suite with more options like downsampling similar to the MPC 2000XL.

There are some limitations right now. MPC 2000 playback and memory storage weren't really designed for anything beyond roughly +/-24 semitones, so going further can produce some weird behavior with longer resamples due to the way the MPC hardware and RAM handle playback. The faster you resample a sample, the more of the tail end can slightly disappear. Mathematically, this shouldn't really make sense, but something in the architecture of the MPC itself is causing it.

I'm currently investigating exactly what's happening there. It's relatively harmless for now, but if you run into the issue, just give your samples a little more length before resampling them, then trim accordingly.

  • Resample Page added under TRIM->Params F5 softkey option
  • Pitch Resampling functionality added
  • Pitch tuning increased to ±480 to compensate for the resampling process
2026-09-13 Mute groups finally feature

Long-awaited feature for the MPC2000 Classic: mute groups. The ability to quickly assign pads to one of 32 different mute groups, with each pad in the group cutting off the other pads assigned to the same group. Simply go to the Program menu and select Mode: Mute. Then cursor over to the ID and select the group you want to assign the pad to.

  • 32 different mute groups available
  • each pad can be assigned to one of the 32 groups through the program menu mode option
2026-09-10 Increased pitch clamp +- one octave feature

For years, my workflow has been to sample at 45 +8 RPM from the tech 12 turntable into the MP, pitch it up another half octave, then resample it into the S950. From there, I sample it back into the MPC2000 and slow it back down to get that 12-bit-style aliased, ringing sound you hear from older machines. My issue was always running out of headroom with the MPC2000's -24 semitone limit. In theory, I could go much lower, which would let me save even more space on my floppies while increasing the aliasing from the pitch-down process. Now you can do this directly with the DMPC2000 OS without needing to link multiple machines together. Prepare your samples accordingly by saving them pitched up higher than you normally would, and you can pitch shift below -24 semitones, all the way down to -36 semitones (-360). The sound is very distorted, but in that classic drum machine way we're used to hearing from SPs and older rackmount units.

  • Pitch range increased by ±12 semitones (±360)
2026-09-07 High pass filter through stock OS? feature

Rip the bandaid off, this is not possible. I initially started this project because I wanted to add a high pass filter to the stock OS. My thought was that it was simply some maths being sent off to a generic filter chip, so in theory I could just flip the polarity. This is not the case, the OS simply sends off params to a LPF filter chip to put it lightly. Those params are adjustable but I don't want to get into the mud here because it would only effect the LPF. If you want that HPF for your unit you need to buy the EB16.
